# CopilotBYOKManager 发布标准

本标准用于首次公开发布的 GO / NO-GO 决策。此前的提交、原型、源码构建和隔离测试均视为开发活动，不视为已发布版本。当前结论是 **NO-GO：尚未满足公开安装包发布条件**。本文件制定标准，不创建标签、安装包或 GitHub Release。

核心承诺：**Provider 一次配置，多端 Copilot 复用。** 自动发布的边界是 VS Code、Copilot CLI 与已审核插件版本的 JetBrains；Copilot App 仍为手动配置。配置写入成功不等于已登录、已选用模型或真实请求成功。

[MVP 规范](mvp-implementation-spec.md)定义必须实现的范围；本文定义如何提供发布证据，不放宽规范。[实现状态](implementation-status.md)记录现有功能和历史证据，[本机验证](local-validation-plan.md)提供执行步骤。

2026-10-14 的四页核心配置版属于开发快照：总览、供应商、应用、关于。用量、账单/独立授权和资源入口暂未开放，具体状态见[功能记录](feature-availability.md)。隐藏功能及其验收记为延期，不是通过；原完整 MVP 发布门槛仍保留。若将核心版作为单独公开发行范围，维护者须先明确批准相应规范，不自动将 G5 或资源消费验收改成 PASS。

## 1. 版本和支持承诺

| 阶段 | 对外状态 | 准入条件 |
| --- | --- | --- |
| 开发快照 | 源码和明确标注的浏览器试用；不叫正式版 | 可复现开发环境；示例数据不能冒充真实客户端 |
| 首次候选版 `v0.1.0-rc.N` | GitHub Pre-release，不设为 Latest | 下列 G0–G7 全部通过；允许列出不影响安全与主流程的已知体验问题 |
| 首次稳定版 `v0.1.0` | 明确支持范围的正式 Release | 同一候选源码再次通过 G0–G7；G8 试用验证通过；维护者签字确认 |

首发验收基线为 **Windows 11 x64**。macOS/Linux 的源码能力和 CI 编译结果不等于安装包或一键安装支持；未经独立验收，不列入正式支持系统。其他 Windows 版本或架构同理。

每次候选版需固定提交 SHA、应用版本、构建工具链、客户端版本和 JetBrains 插件发行版。不得用“支持全部最新版”替代版本表。发布后修复生成新版本和新哈希，不悄悄替换已经验证过的二进制。

## 2. 发布门槛

维护者负责最终决定；测试执行者填写证据。一个人可兼任，但“待验证”“受阻”和“失败”都不能记为通过。每项证据必须包含源码 SHA、日期、环境、步骤、结果和脱敏产物位置。

| Gate | 必须满足的条件 | 最低证据 |
| --- | --- | --- |
| G0 范围与身份 | 产品名、窗口、包名、可执行文件、应用 ID、配置目录、凭据服务和受管标记一致；仅使用产品自己的命名空间；功能宣传与支持表一致 | 元数据检查、干净用户首次运行、安装包信息；不导入其他应用的数据或凭据 |
| G1 源码质量 | 锁定依赖；全部必需检查通过；提交中没有真实密钥、数据库、日志或临时安装器；新增依赖说明用途和许可 | 对候选 SHA 的 CI 链接和本地检查摘要；不是不同提交的拼接结果 |
| G2 部署与恢复安全 | 原生持有、15 分钟到期且单次消费的预览；写前指纹重检；全部目标先准备；日志先于写入；外部变化拒绝覆盖；恢复失败保持只读；未受管数据保留 | 临时目录回归及最终源码的 NativeIsolated 完整套件；覆盖并发、二次提交、写入中断、回滚冲突和密钥脱敏 |
| G3 安装与启动 | 在干净 Windows 用户/VM 中，无开发工具也能安装、打开、关闭和再启动；WebView2 缺失/离线/权限拒绝行为明确；卸载不删除用户客户端或其他软件数据 | 从最终待发布安装包完成的逐步记录；签名、版本、架构、文件哈希；组件安装后重新检测而非只看退出码 |
| G4 实际客户端 | 下表中宣称支持的路径都完成真实验收；不把浏览器 fixture、配置文件或截图当作模型调用证明 | 每个目标的版本、独立登录观察、模型可见性、最小请求结果；只保留元数据，不保存对话或密钥 |
| G5 账号与用量 | 客户端官方登录与管理器账单授权分开；未知/过期/部分覆盖不是零；不同账单单位不相加；估算使用精确小数；来源启停/清除范围正确 | 受控账号下的官方运行时和个人账单结果，或有依据的 NotCovered；选择性导入、共享去重、缺失 Token 与零费用回归 |
| G6 中英文与可用性 | 所有程序自有控件、状态、提示和无障碍标签均有中英文；语言切换不写客户端、不丢表单/预览；键盘可完成核心任务 | 双语消息检查、隔离浏览器流程、最终 WebView2 实测；960 × 640 与 1180 × 760、100%/150% 缩放、长名称、空/错/忙状态 |
| G7 交付与支持 | 英文默认 README 和中文手册一致；安装、首次使用、撤销、已知限制和安全反馈可找到；安装包可验证，安全上报入口实际可用 | 版本支持表、发布说明、SHA-256 清单、许可证及依赖说明、脱敏截图、恢复说明；维护者检查下载链接与安全入口 |
| G8 小范围试用 | 至少 5 名自愿测试者，包含中英文环境；至少 80% 且不少于 4 人无需维护者代操作，完成添加连接→预览→发布→客户端选用→撤销；候选版连续 7 天无未解决的 P0/P1 | 自愿反馈表，以实际开始流程的人为分母，记录逐步成功/失败及耗时；不添加默认遥测；修复 P0/P1 后重新开始观察期 |

G8 的人数和观察期是本项目的起始验收标准，不是市场预测。主流程未通过时延后发布时间，不降低数据安全要求凑发布日期。

四页版的 G6 还需核对浅色/深色/跟随系统、偏好保存失败、主题切换保留表单及预览、应用页供应商选择不因切换语言而改变，以及 Windows 关闭至托盘/直接退出选项及重启保存、左键恢复、右键退出、菜单跟随语言和重复启动唤回同一窗口。托盘不可用、隐藏失败或偏好损坏时正常退出；损坏文件保留，禁止隐藏后失去恢复入口。退出须确认进程结束及托盘消失，不能只确认窗口关闭。编译、浏览器及单元测试不能代替实际系统交互验收。

### G1 必跑检查

从仓库根目录运行，使用待发布 SHA 和锁文件：

```bash
npm ci
npm run check:web
cargo fmt --all -- --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
git diff --check
```

`check:web` 包含双语文案、参数占位符及漏翻译检查。另需在隔离环境运行浏览器回归、NativeIsolated 和最终安装包验收。`npm run build -- --no-bundle` 仅证明无安装器构建，不满足 G3/G7。当前 `bundle.active` 为 `false`，打包和签名仍是待实施项。

### G4 客户端逐项验收

| 客户端 | 正向路径 | 必测边界 |
| --- | --- | --- |
| VS Code Stable / Insiders / profiles | 同一 Provider 发布后模型可选；官方登录后完成经授权的最小请求 | 保留其他供应商与用户配置；陈旧预览拒绝；撤销仅移除本软件受管项；不弹出意外编辑器窗口 |
| Copilot CLI | 主动勾选 CLI；发布后新开终端和会话，核对 `COPILOT_MODEL` 并请求 | 单一路由语义；`providers.json` 遮蔽时阻止误发布；撤销/恢复后核对环境；不声称同时使用 GitHub 官方路由 |
| JetBrains | 至少两个真实 IDE/profile：各自官方登录、关闭后发布、重开选用并完成最小请求 | 固定已审核插件版本；共享配置只写一次且说明未勾选 IDE 也可能可见；独立账号确认；未知/禁用插件不写；其他供应商保留 |
| Copilot App | 完成手动 Provider 指引并在 App 内选用、请求 | 自动写入和自动验证不受支持，界面与说明均不得声称已同步或已验证 |

一次 Provider 配置能否复用，要在上述目标实际证实；不能用为每个客户端分别手工输入的测试代替自动发布验收。真实请求必须由维护者明确授权供应商、模型和费用边界；只发送不含项目内容的最小消息。账号登录、许可和隐私确认仍需相应授权。

资源消费也需真实验证：只对文档中已审核的 MCP/Markdown Skill/Instructions 路径做发布与撤销；不承诺命名配置、自定义根目录或未审核客户端的自动消费。用量中的预期 NotCovered 需要接口/权限/覆盖依据，不可用来掩盖应用错误。

## 3. 安全、签名和产物要求

- 日志、截图、issue、发布附件不得包含 API key、令牌、请求头值、原始会话、项目代码或可还原的私人路径。审阅 [SECURITY.md](../SECURITY.md) 后再上传附件。
- 发布应用本体与安装器都需核验预期发布者、签名及 SHA-256。签名证书或托管签名权限由维护者保管，不写入仓库。购买证书或云服务需另行批准。
- 签名不等于没有 SmartScreen 提示：新文件仍可能需要信誉积累。记录实际下载/安装表现，不指导用户关闭安全防护。参见 [Microsoft SmartScreen 开发者说明](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)。
- 为正式分发选择一种主安装器并验收后再增加格式。Tauri 支持 Windows NSIS 与 MSI；实际配置、WebView2 策略和签名流程按 [Windows 安装器文档](https://v2.tauri.app/distribute/windows-installer/) 与 [签名文档](https://v2.tauri.app/distribute/sign/windows/)执行。
- GitHub Release 先建草稿，核对附件后再公开，候选版标记 Pre-release。若启用不可变 Release，公开后不能替换附件；必须在草稿阶段传齐。参见 [GitHub 发布管理](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)。

最低交付清单：最终安装器、`SHA256SUMS.txt`、对应源码 SHA/tag、工具链/依赖锁文件、构建来源证据、中英文发布说明、支持矩阵与已知问题、[用户手册](../README.md)、[中文手册](../README.zh-CN.md)和有效安全反馈入口。CI 临时附件不替代正式下载入口。

## 4. 缺陷与停止条件

| 级别 | 例子 | 处理 |
| --- | --- | --- |
| P0 | 密钥泄露、越权读认证、任意执行、破坏用户文件或覆盖外部修改 | 立即停止发布和推广，优先私下处理；不等待试用周期结束 |
| P1 | 核心客户端不可用、错误模型/端点发布、无法安全恢复、金额/单位误导、安装无法启动 | 阻止 RC 和正式发布；修复并重跑相关及全量门槛 |
| P2 | 非核心流程可绕过的体验问题 | 公开说明影响、替代步骤、负责人；不得掩盖安全或主流程问题 |
| P3 | 不影响理解和操作的排版或文字问题 | 可进入后续修订；危险操作的误译不属于 P3 |

上线后出现 P0/P1：暂停新的宣传，发布清晰风险说明并停止推荐受影响版本；保留问题版本的哈希与证据，提供经核验的修复版本。不自动降级客户端、不强制覆盖外部修改，不要求用户上传敏感数据库。首发没有可回退的“上一正式版”；必要时建议停止写入并按安全恢复指引操作。

## 5. 当前缺口与执行顺序

1. 本次身份与双语变更已通过源码自动检查和隔离浏览器验证；完整结果见[实现状态](implementation-status.md#validation-evidence)。仍需在最终源码上重跑 NativeIsolated，不能用测试工具自身的单元测试代替原生套件。
2. 实施和审核发布打包、签名、WebView2 策略、校验和产物流程；补齐规范内尚缺的 App 直接下载策略，不把“暂未实现”写成上游不支持。
3. 在干净 Windows 环境完成安装、账号、用量、资源以及客户端实际请求验收。JetBrains/Rider 真机工作此前被维护者暂停，未经恢复授权不继续；该项暂不通过。
4. 通过 G0–G7 后，由维护者决定是否发布 RC；完成 G8 后再决定首次稳定版和广泛推广。
