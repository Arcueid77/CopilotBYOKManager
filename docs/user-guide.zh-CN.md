# CopilotBYOKManager 用户手册

[English](user-guide.md) | **简体中文**

[项目介绍](../README.zh-CN.md) · [发行与安装包说明（英文）](release-engineering.md)

**Provider 一次配置，安全发布到多个 Copilot 客户端。**

在一个地方保存 AI 供应商的接口地址、API 密钥和模型，再预览并发布到 **VS Code、Copilot CLI 和已审核插件版本的 JetBrains**。Copilot App 提供手动配置引导。

不用为每个客户端重新维护一份 Provider。换地址、换密钥或增减模型时，修改连接，再预览并发布到需要更新的客户端即可。

[开始使用](#getting-started) · [支持的客户端](#supported-clients) · [首次配置](#first-connection) · [日常管理](#everyday-use) · [未推出功能](#usage) · [常见问题](#faq)

桌面安装包在 [Releases](https://github.com/Arcueid77/CopilotBYOKManager/releases) 下载，安装方式与校验和见对应版本说明。

界面支持**简体中文和英文**。首次启动跟随系统语言，其他语言默认英文；可在顶部的“界面语言”中切换并记住选择。请先完成或关闭正在编辑的表单、发布预览再切换。连接名称、模型 ID、端点和诊断原文保持不变，不做翻译。

## 当前四个页面

| 页面 | 主要操作 |
| --- | --- |
| 总览 | 查看配置状态、待处理事项、下一步和最近发布结果 |
| 供应商 | 管理地址、密钥、模型，预览发布及撤销受管配置 |
| 应用 | 为应用选择供应商，核对检测、安装、官方登录和发布记录 |
| 关于 | 窗口行为、帮助、离线规划记录、本地存储与恢复信息 |

在顶部的 **外观**中选择 **跟随系统、浅色、深色**，偏好会单独保存。切换主题不会丢失表单草稿或发布预览。

Windows 默认关闭至托盘。在 **关于 → 关闭窗口时**选择 **收起到系统托盘**或 **退出程序**，选择会保存。左键点击托盘图标或选择 **打开主窗口**恢复；右键选择 **退出 CopilotBYOKManager**结束程序。普通最小化仍留在任务栏。再次打开程序会唤回已有窗口，不另开实例。托盘菜单跟随界面语言。

托盘创建失败、隐藏失败或窗口偏好无法读取时，关闭按钮正常退出；损坏的偏好文件保留，不自动覆盖。实际行为以关于页读取的状态为准。浏览器试用没有系统托盘。

## 它能帮你做什么

- **统一管理 Provider：**保存多个供应商，获取或手动填写模型，设置推荐模型。
- **将配置应用到多个客户端：**选择目标、查看变更、确认发布，并逐项查看结果和下一步。
- **维护客户端：**检查安装状态，按审核过的计划安装支持的 Windows 组件，逐个完成官方登录与账号核对。
- **聚焦核心流程：**总览、供应商、应用、关于。用量、账单和资源入口暂时隐藏，已有数据保留。

界面中的“供应商”就是一份可复用的 Provider 配置；“发布”是把它写入选定客户端。保存供应商后，选择应用并发布，再在应用中选用模型。

<a id="supported-clients"></a>

## 支持的客户端

| 客户端 | Provider 配置方式 | 使用前需要知道 |
| --- | --- | --- |
| VS Code Stable / Insiders 及检测到的配置档案 | 自动添加或更新本连接的供应商分组，保留其他供应商 | 发布后，在对应配置档案的 Copilot 模型选择器中选用 |
| GitHub Copilot CLI | 自动写入 `providers.json`，多个供应商与模型共存 | 默认不勾选；确认发布后启动新会话，用 `/model` 选择 |
| JetBrains IDE 中的 GitHub Copilot 插件 | 对审核过的插件版本自动写入共享 BYOK 配置 | 先关闭相关 IDE，发布后重新打开、登录并选用模型 |
| GitHub Copilot App | 提供配置步骤，不自动写入 Provider | 在 App 内手动添加供应商并验证 |

JetBrains 适配器仅针对[版本表中的 1.19 插件发行版](jetbrains-support.md#version-and-compatibility-boundary)。使用同一运行时目录的 IDE 会共享配置，包括未勾选的 IDE。

各客户端可接受的协议、地址和模型能力可能不同，以发布预览为准。本软件管理配置，不提供模型服务、订阅或免费额度，也不替代客户端自身的权限要求。

## 开始使用

### 安装桌面版

在 [Releases](https://github.com/Arcueid77/CopilotBYOKManager/releases) 选择版本：Windows x64 可运行 Setup，或解压免安装 ZIP 后运行 `copilot-byok-manager.exe`。macOS 15+ 打开 Universal DMG，将应用拖入 Applications。Windows Setup 会在需要时下载 WebView2；免安装版与安装版使用相同的用户数据目录。

### 先试用界面，不改动电脑配置

1. 在本仓库页面选择 **Code → Download ZIP**，下载并解压源码。
2. 用浏览器打开本地的 [apps/desktop/web/index.html](../apps/desktop/web/index.html)。
3. 尝试添加供应商、选择应用和查看发布预览。

页面会显示“浏览器试用”。该模式使用模拟数据，不写入真实客户端、不执行安装或登录，也不向 Provider 发起请求；请使用示例数据，不要填写真实密钥。本核心配置版暂未开放用量、账单和资源管理。

[交互设计原型](../prototype/copilot-byok-manager.html)另行保留供设计参考；体验当前界面请使用上面的前端入口。

### 启动可实际配置客户端的桌面版

准备 Git、Node.js 22+、Rust 1.88+，以及 [Tauri 2 的系统依赖](https://v2.tauri.app/start/prerequisites/)。Windows 还需要 MSVC C++ 构建工具和 WebView2；macOS/Linux 请按官方依赖说明准备环境。

在终端中运行：

```bash
git clone https://github.com/Arcueid77/CopilotBYOKManager.git
cd CopilotBYOKManager
npm ci
npm run dev
```

当前开发分支是 `main`。首次启动需要下载依赖并编译；成功后会打开 CopilotBYOKManager 桌面窗口。

如需构建不带安装器的桌面程序，运行 `npm run build -- --no-bundle -- --locked`。Windows NSIS / 免安装 ZIP 和 Mac 测试 DMG 命令见[发行工程（英文）](release-engineering.md)。免安装版的状态、系统凭据与目标配置使用用户存储。

## 首次配置：从一个 Provider 到多个 Copilot

### 1. 确认要使用的客户端

进入 **应用**，查看已检测到的应用和配置档案。总览每行的 **查看应用**会定位对应应用。只需准备自己要用的客户端，不必全部安装；未安装、不支持或检测不可用不会变成总览待办。

- 已安装但状态未更新：在 **安装与更新** 中点击 **重新检测**。检测不可用的组件会保留具体原因，并提供同名按钮；重新检测只读取状态。
- 缺少支持的 Windows 组件：点击对应组件的 **安装**，核对计划后再确认；不支持自动安装的客户端需自行安装。

安装窗口会分别显示每个组件的阶段、下载量、可用的百分比和已用时间；下载大小未知时显示动态进度条。点击 **取消安装**会停止剩余任务，已完成组件仍显示成功。新装好的 Copilot CLI 无需重启管理器即可检测到；**重新检测**也会读取 Windows 的最新搜索路径。
- 展开 **登录与账号检查（可选）**，按提示在各客户端完成官方登录。软件不会把一个客户端的登录凭据复制给另一个客户端。

在各客户端自行核对后，可以通过 **记录已核对的账号**保存记录。这不会登录或切换客户端账号，发布供应商也不要求账号对齐。手动确认和软件已核验身份会分别显示。**配置 Provider 不要求先授权本软件读取个人账单**，账单授权独立于应用登录，本核心配置版暂未开放该入口。

### 2. 添加供应商

进入 **供应商 → 添加供应商**，填写：

| 字段 | 应该填写什么 |
| --- | --- |
| 名称 | 便于识别的名称，例如“工作用 Provider” |
| 端点地址 | 供应商提供的 API 基址，不是官网或控制台地址 |
| API 密钥 | 该供应商的密钥；只有允许匿名访问的端点才可留空，目标客户端也须支持 |
| 模型 | 通过“获取模型”添加，或手动填写上游模型 ID |

`https://api.example.com/v1` 只是地址格式示例，不能实际调用。远程端点需使用 HTTPS；本机回环地址可使用 HTTP。

获取模型前先看 **当前协议**。若供应商并非默认的 OpenAI 兼容 Chat Completions 接口，点击 **更改协议**，展开 **高级选项：供应商类型、接口协议与请求头**：

- 按供应商说明选择 **Chat Completions、Responses 或 Messages**。
- 更改供应商类型不会自动修改地址或协议；请分别核对。
- 仅在需要时填写请求头，每行采用 `名称: 值`。用 `${apiKey}` 引用密钥，不要把真实密钥写进请求头文本。

API 密钥在管理器中保存在系统凭据库，不会回显到表单。发布时，部分客户端格式需要将密钥写入其配置，相关文件不能公开分享。

### 3. 添加模型并保存

推荐先点击 **获取模型**，按名称或 ID 筛选，勾选需要的模型：它会立即加入同一个可编辑草稿。点击 **保存供应商**时，勾选和手动填写的模型一起保存，不再需要另点“添加已选”。不会自动全选，也不会覆盖已有的手动名称或停用设置。取消勾选会移除尚未手动修改的目录新增行；更改端点或凭据设置会清除未保存的目录勾选，保留已配置和手动修改的模型。

供应商不提供模型目录时，可以直接在 **模型**中每行填写一个模型：

```text
your-model-id | 工作模型
another-model-id | 备用模型
```

请把示例 ID 换成供应商实际提供的 ID；竖线后的显示名称可以省略。Azure 连接需手动填写实际部署名称，不能直接用基础模型名称替代。

选择 **推荐模型**，然后点击 **保存供应商**：

- 发布后，在各应用内选用实际模型。
- VS Code、JetBrains 等有模型选择器的客户端仍需在客户端内选择。

“获取模型”和“测试模型目录”查询供应商的模型列表。保存后，发布到要使用的应用。

### 4. 发布配置

应用卡片先列出已配置的供应商名称和模型数量，再提供 **本次发布**选择。这个选择用于添加或更新配置，实际使用哪个供应商仍由应用内的模型选择决定。未配置、读取失败和不支持的格式会分别显示；发布结果标明供应商与目标应用。

1. 在连接卡片上点击 **发布到应用**。
2. 逐个核对目标，取消不需要的客户端或配置档案。**Copilot CLI 默认不勾选**，需要发布其供应商与模型时再主动选择。
3. 如果包含 JetBrains，先关闭使用该共享配置的相关 IDE。
4. 点击 **发布配置**，普通发布会自动检查并执行，然后显示结果。需要先核对明细时，可选 **查看变更**。标为“需手动处理”的目标仍需手动配置。
5. 发布到 CLI 或移除供应商分组时，会先显示变更；核对后点击 **确认发布**。

每次发布都使用有效期 15 分钟、只能使用一次的原生计划。计划过期或配置发生变化时会拒绝执行；核对错误后重试会重新检查，CLI 发布和移除分组仍需再次确认。

完成后，在 **总览 → 最近一次发布**或 **供应商 → 最近配置操作**查看各目标的结果。这里会保留需要重启、手动处理或选用模型的提示，不必依赖短暂弹出的通知。

没有供应商时，总览显示 **添加第一个供应商**；已有供应商时，顶部的 **发布到应用**进入供应商页。应用行的 **查看应用**定位对应卡片。支持且已配置的应用排在前面，其次是支持但未配置的应用；JetBrains 逐个显示插件支持状态。Copilot Chat 对应 VS Code 默认档案，与其共用目录的内置 Agents 使用同一张卡片。改变发布选择会使闲置预览失效，切换语言保留选择。发布过程中不能切换页面、刷新或收起预览；失败时核对发布记录与恢复状态，再生成新预览。

### 5. 到客户端里选用并验证

**VS Code**

打开发布时选中的配置档案，在 Copilot 的模型选择器中选择刚发布的模型。多个 Provider 可以保留在不同分组中，实际用哪个模型由客户端选择。

**Copilot CLI**

供应商与全部启用模型写入 `~/.copilot/providers.json`（Windows 为 `%USERPROFILE%\.copilot\providers.json`）。逐个发布多个供应商即可共同保留，在新的 CLI 会话中用 `/model` 选择。相同模型 ID 可以分属不同供应商；更新一个供应商不会替换其他供应商，已选默认模型也会保留。未登录 GitHub 时，可用 `copilot --model <供应商ID>/<模型ID>` 启动，ID 见发布预览的写入明细。协议支持 Chat Completions、Responses 和 Messages，Ollama 等本地接口可以不填密钥。

自定义 `COPILOT_HOME` 或 `COPILOT_PROVIDERS_CONFIG` 暂不自动发布。重新发布同一供应商时，会同时清理本软件拥有的旧环境配置；这种升级完成后请新开终端。其他旧环境配置保留不动。详见[CLI 配置说明](copilot-cli-support.md)。

**JetBrains**

重新打开对应 IDE，完成 GitHub Copilot 官方登录，在 Copilot Chat 的模型选择器中选用已发布模型。请在每个 IDE 中分别登录并选用模型。未知插件版本不会自动写入；更多限制见[JetBrains 使用与兼容说明](jetbrains-support.md)。

**Copilot App**

下面是当前版本的操作。[实验性 SQLite 同步](copilot-app-sqlite-sync.md)已批准但尚未实现：未来默认关闭，需手动开启并确认风险后才自动同步；v0.1.0 没有这个开关。

在应用卡片上选择 **本次手动配置**的供应商，再点 **手动配置**。确认记录按供应商分别保存，并显示 **你已确认**。修改供应商后会显示 **修改后待确认**；在 App 中更新对应配置后，重新打开指引确认即可。

在 App 的 **Model providers**中添加供应商，填写指引中的地址与模型，并在 App 内输入密钥。完成后回到管理器的指引，点击 **我已完成手动配置**。

如果本次发布包含 App，也可直接点击结果里的 **查看该连接的手动配置步骤**。指引绑定本次连接，不会误用其他地方选中的 Provider。

最后，在要使用的客户端里发送一条不含敏感项目内容的简短请求，确认模型能正常响应。真实请求可能产生供应商费用。

<a id="everyday-use"></a>

## 日常管理

### 修改地址、密钥或模型

在 **供应商**中找到 Provider，点击 **编辑**：

1. 修改相应字段。已有密钥留空表示保留；替换时输入新密钥，删除时勾选 **移除已保存的密钥**。
2. 点击 **保存供应商**。
3. 再次 **发布到应用 → 发布配置**，更新需要的目标；CLI 发布或移除分组时再确认变更。
4. 按发布结果提示重新打开客户端或新建会话。

修改连接不会后台自动同步到所有客户端。若修改了端点、协议或请求头后获取模型提示需要凭据，请为当前端点重新输入密钥，软件不会静默把已存密钥发到变更后的地址。

### 增加或切换 Provider

在 **供应商**中添加另一份连接，再发布到所需客户端：

- VS Code / JetBrains：多个供应商分组可共存，去客户端模型选择器切换。
- Copilot CLI：多个供应商和模型共同保存在 `providers.json`。选择供应商、查看预览并确认，只更新该供应商；手动配置和其他供应商会保留。完成后启动新的 CLI 会话并选择模型。若配置在预览后发生变化，重新预览并确认即可。
- Copilot App：在 App 内手动添加或切换。

在各客户端的模型选择器中切换当前使用的模型。

### 停用、停止管理和撤销有什么区别

| 操作 | 管理器中的变化 | 客户端中的变化 |
| --- | --- | --- |
| 关闭供应商的“允许发布”开关 | 保留供应商，暂停新的发布 | 已发布配置仍保留 |
| **移除 → 仅停止管理… → 确认停止管理** | 删除连接、发布记录、受管证明及专用凭据 | 配置和其中已写入的密钥仍保留，之后由你自行管理 |
| **移除 → 预览撤销并删除 → 确认撤销并删除** | 撤销成功后删除连接 | 仅清理能核验为本软件管理的配置，不删除其他供应商 |

**想让客户端不再使用这份配置，请选择“撤销并删除”，不要只停用连接。**撤销前核对预览中的所有目标；它会处理该连接已发布的受管配置，不只是某一个客户端。

总览与应用页在刷新时读取当前配置：手动修改会直接显示，删除的供应商不再显示；读取失败会单独提示。重新发布或撤销本软件拥有的供应商时，以当前内容为准。生成计划后再次发生修改会停止写入，写入后再次发生修改会停止回滚。归属冲突仍需核对。先查看 **应用 → 发布与撤销记录**与 **关于 → 本地存储与安全**中的恢复状态，不要直接删除配置文件或备份。

## 已规划但暂未推出的功能

官方配额、个人账单及独立授权、本地模型/会话用量、费用估算、MCP/Skills/Instructions 暂未开放。实现和已有数据保留，但四页界面不会加载这些模块或执行相关操作。

[功能记录](feature-availability.md)区分“已有实现但隐藏”“尚未实现”和“待验收”。在 **关于 → 未推出功能记录**也可离线查看简短清单，不承诺上线日期。

## 常见问题

### 已经保存连接，为什么客户端没有变化？

保存只更新管理器。还要点击 **发布到应用 → 发布配置**，然后按客户端要求选模型、重启 IDE 或新开终端。更新已有连接也是同样的流程。

### “测试模型目录”成功，为什么聊天仍然失败？

它只检查模型目录接口。请继续核对模型 ID、接口协议、客户端支持的能力、账号权限和供应商可用额度，并在实际客户端中验证。

### 获取不到模型，能不能继续配置？

可以。若供应商没有兼容的目录接口，直接手动填写模型 ID；Azure 填部署名称。如果提示权限被拒绝、网络错误或格式不支持，先核对地址、密钥和供应商文档。

### 发布后仍看不到模型，先查哪里？

先查看 **总览 → 最近一次发布**的逐目标结果，再核对：

1. 是否发布到了实际正在使用的 VS Code 配置档案或 JetBrains 运行时目录。
2. 该目标是自动写入成功，还是仍需手动处理。
3. IDE 是否需要重新打开，CLI 是否在新终端、新会话中运行。
4. 插件版本和客户端是否受支持；JetBrains 尤其需要核对固定版本表。
5. 客户端是否已完成官方登录，并在模型选择器中主动选用。

“应用配置状态”只核对本软件发布的配置。

### CLI 提示已有配置冲突，或者我想回到官方路由怎么办？

先核对 `providers.json` 是否为有效的供应商/模型数组，以及是否设置了自定义配置路径。格式不受支持、文件不可读或预览后的内容变化都会阻止写入；修复对应问题后重新预览即可。

使用对应供应商的 **预览撤销并删除**，核对目标后确认，只会移除它自己的受管分组；其他供应商保留。启动新会话后选择剩余模型或 GitHub 官方模型。若注册表已空，保留的独立环境变量路由可能重新生效，需要一并核对。

### 为什么 JetBrains 不支持我的版本？

自动写入只对已审核的确切插件发行版开放。较新、未知、禁用或自定义路径中的插件可能需要手动处理。请提供 IDE 与插件版本反馈兼容性问题，不要为绕过检查修改版本标记。

### 为什么发布按钮不可用，或者要求重新预览？

检查连接是否启用，以及是否出现只读恢复提示。修改目标、配置变化、预览使用过或超过 15 分钟后，都需重新生成预览。如果提示上次操作中断，先按 **核对安全恢复**引导处理；详情在 **关于 → 本地存储与安全**和 **应用 → 发布与撤销记录**。

### 为什么找不到用量、账单或资源页？

本版先聚焦供应商配置与发布，相关入口暂时隐藏，不会删除已有记录。开放条件见[功能记录](feature-availability.md)。

### 密钥和数据放在哪里？能否直接分享配置排查问题？

在 **关于 → 本地存储与安全**中查看实际状态文件位置。管理器的 API 密钥与独立 GitHub 授权存放在系统凭据库；发布后的客户端配置及私有回滚数据可能包含密钥。

不要分享完整配置、数据库、环境变量、回滚文件或原始会话日志。反馈时只提供版本、操作步骤、脱敏后的错误和状态。完整规则见[安全说明](../SECURITY.md)。

## 隐私与当前边界

- 不复制客户端的 OAuth Token、浏览器 Cookie、VS Code SecretStorage 或 JetBrains Password Safe。
- 用量导入只持久化允许的元数据，不保存或上传提示词、回复、源代码、工具内容或原始日志行。
- 发布前展示变更，并保留受管写入的恢复信息；目标被外部修改后不会强行回滚覆盖。
- 当前不提供组织/企业账单、Provider 发票查询、云端用量同步、超额付费设置，也不提供完整的 macOS/Linux 一键安装。
- 已实现能力与验证进度见[实现状态](implementation-status.md)。
